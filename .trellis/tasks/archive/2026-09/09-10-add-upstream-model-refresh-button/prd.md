# 为 cmdcode2api 模型页增加上游模型刷新按钮

## Goal

在 ssh2 上 `cmdcode2api` 的 WebUI「模型」页增加“从上游刷新模型”按钮，让管理员无需重启容器即可重新请求 CommandCode 官方模型目录并刷新页面列表。

刷新只同步目录，不自动开放模型：已有模型保持原来的开放/隐藏状态；本次新发现的模型默认隐藏，由管理员之后自行勾选开放。

## Confirmed Facts

- 目标服务位于 ssh2：`/opt/cmdcode2api`，容器名为 `cmdcode2api`，当前通过 Docker 镜像 `cmdcode2api:custom-usage` 运行。
- 上游目录接口为 CommandCode 的 `/provider/v1/models`。
- 当前后端在启动时或新增首个账号时调用 `FetchProviderModels`；模型目录只保存在进程内的 `modelCatalog`，没有现成的手动刷新 API。
- 当前管理 API 只有 `GET /admin/api/models` 和 `PUT /admin/api/models`：前者读取已加载目录及 `exposed` 状态，后者保存 `exclude_models`。
- 当前模型页已有搜索、全选、全不选和逐项即时保存功能；空目录时显示“模型目录为空（上游未返回）”。
- 当前 `FetchProviderModels` 返回值为 `void`，失败只写日志；模型目录在多个请求路径中直接读取，没有统一的运行时并发保护。新增刷新按钮需要可报告错误、保留旧目录并避免 data race。
- `exclude_models` 是暴露策略的持久化来源：命中它的模型会从 `/v1/models` 隐藏并被拒绝调用。之前已确认模型开放由管理员手动选择，因此刷新不能把新模型默认暴露。
- ssh2 宿主机的 Go 版本为 1.19.8，而项目 `go.mod` 要求 Go 1.25；直接在宿主机执行现有 `go test ./...` 会因 `http.Request.PathValue` 不存在而失败。验证必须使用 Go 1.25 的 Docker 工具链或构建环境，并把该基线限制与本次改动区分开。

## Requirements

### R1. 管理员刷新接口

新增仅限现有管理员认证保护的接口（建议 `POST /admin/api/models/refresh`）。接口使用当前启用的 primary CommandCode 账号请求上游目录；成功时原子替换进程内目录并返回非敏感的刷新摘要；没有启用账号、上游请求失败、响应无法解析或返回空目录时返回明确的非 2xx 错误。

失败不得清空或替换已有目录，也不得返回 API key、管理密码或上游原始敏感响应。

### R2. 目录与暴露状态分离

刷新只更新上游目录，不调用 `PUT /admin/api/models` 的用户选择逻辑。提交新目录时：

- 已存在于旧目录的模型保持原来的 `exposed` 状态；
- 新发现的模型默认 `exposed: false`，必要时将其精确 ID 追加到 `exclude_model_ids` 并持久化，以防刷新后意外开放；若已有排除前缀已经覆盖该模型，则不重复追加；
- 已从上游移除的模型不再显示，已有的旧排除项按现有兼容规则保留；
- 配置持久化失败时恢复旧目录和旧排除列表，不能留下半更新状态。

### R3. 并发与运行稳定性

同一时间只允许一个上游刷新请求。重复点击或并发 API 请求必须被按钮禁用和后端并发保护共同拦截，不产生重复上游请求。模型目录的替换、读取、模型名解析、管理台概览和 `/v1/models` 过滤必须使用一致的快照/锁策略。

### R4. 模型页按钮

在模型页标题区域增加清晰的“从上游刷新模型”按钮。点击后：

- 按钮和相关模型操作控件显示进行中状态并暂时禁用，防止重复操作；
- 成功后重新请求 `GET /admin/api/models`，显示加载数量、新增/移除数量和刷新成功提示；
- 失败时保留当前页面列表，显示可理解的错误提示，并恢复按钮可用状态；
- 刷新后以服务端保存的 `exposed` 状态重新渲染，新模型显示为未勾选。

### R5. 兼容现有模型操作

搜索、全选、全不选、逐项勾选和即时保存行为保持不变。刷新与正在进行的模型保存请求不能互相覆盖；后端必须以最新配置为基础提交新模型的默认隐藏状态。

### R6. 文档、测试与部署

更新中英文 README 的管理 API/模型页说明；为后端刷新成功、上游失败/空目录、无启用账号、重复刷新、目录替换、暴露状态保留和新模型默认隐藏增加测试；对嵌入式前端 JavaScript 做语法/定向验证。构建新镜像前备份 ssh2 远程源码、Compose、配置和当前镜像，部署后验证健康检查、刷新 API、管理模型目录和 `/v1/models`。

## In Scope

- `cmdcode2api` 后端刷新接口、上游请求错误处理、目录快照并发保护和默认隐藏新模型的持久化。
- WebUI 模型页刷新按钮、忙碌状态、提示和重新加载逻辑。
- 相关 Go/前端测试、README 更新、远程备份、构建、部署和生产验证。

## Out of Scope

- 自动开放任何新模型或替管理员勾选模型。
- 修改 CommandCode 账号、API key、客户端 key、管理密码、代理或用量数据。
- 改变模型请求转发协议、计费逻辑或模型 ID 映射规则。
- 更新其他服务器或其他 WebUI 页面。
- 引入新的前端框架或第三方依赖。

## Open Questions

- None currently blocking. 用户此前已明确模型由自己开放；本功能采用“新模型默认隐藏、管理员手动勾选”的策略。

## Acceptance Criteria

- [x] 管理员点击模型页刷新按钮后，后端向上游请求最新模型目录并在无需重启的情况下更新管理台目录。
- [x] 刷新成功响应包含可供 UI 展示的加载数量、新增/移除数量和刷新时间等非敏感结果。
- [x] 上游失败、空目录、无启用账号和配置保存失败均返回非 2xx，旧目录与旧暴露策略保持不变。
- [x] 已有模型的 exposed 状态保持；新模型默认未勾选且不会出现在对外 `/v1/models` 中，除非管理员随后手动开放。
- [x] 并发刷新最多产生一次上游请求；模型目录读写无 data race，模型保存与刷新不会丢失用户选择。
- [x] 按钮在请求期间防重复点击，成功/失败后都恢复可用，并给出明确提示。
- [x] 现有搜索、全选、全不选和逐项保存行为回归通过。
- [x] Go 1.25 环境下后端测试与构建通过；前端 JavaScript 定向检查通过。
- [x] ssh2 部署前存在可回滚备份；部署后容器、`/health`、刷新 API、管理模型目录和 `/v1/models` 验证通过，无 API key/密码泄露。
