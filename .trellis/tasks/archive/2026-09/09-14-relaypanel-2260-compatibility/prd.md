# 仅在 VPS 部署 3x-ui + Xray

## Goal

仅在 SSH 目标 `vps`（`67.103.169.18`）上部署 `3x-ui + Xray`，由 3x-ui 管理新用户、入口、订阅、流量和到期策略；新用户流量从 VPS 本机统一出站。

本任务严格限制在 VPS：不连接、检查、修改或依赖任何其他主机；现有 VPS 服务必须并行保留。

## User intent

用户已确认：

- 采用 `3x-ui + Xray`，不再部署 RelayPanel；
- 需要 B 类能力：面板统一管理用户入口和流量出口；
- 全程只涉及 VPS；
- 现有的 `2260` 通道不能被移除；
- 新用户侧入口使用 VLESS + Reality；
- 3x-ui 面板允许公网访问，但必须有凭证校验。

## Confirmed facts

### VPS 当前状态

- SSH 目标为 `root@67.103.169.18:22`；本任务后续只允许对该目标执行操作。
- Debian 12 (bookworm)、x86_64、1 vCPU。
- 内存约 926 MiB，Swap 约 512 MiB；根盘 9.9 GiB，可用约 7.3 GiB。
- 已安装 `sing-box 1.13.19`，运行于独立的 `sing-box.service`。
- 现有监听：
  - `2262/tcp`：sing-box VLESS Reality 入站；
  - `2263/tcp`：sing-box 认证 SOCKS5 入站；
  - `22/tcp`：SSH。
- VPS 当前只读检查中没有发现 `2260/tcp` 监听；现有 sing-box 配置的出站为 `direct`。因此部署时的 `2260/tcp` 将是新建的 Xray 入站，不覆盖当前已存在的本地服务。
- VPS 尚未安装 Xray、3x-ui、Docker、Podman、Caddy 或 Nginx；有 Python 3 和 wget。

### 3x-ui / Xray 资料

- 3x-ui 是 Xray-core 的 Web 控制面，支持多协议入站、每客户端流量/到期/IP 限制、订阅、统计、多节点和 outbound/routing。
- 当前稳定版本检查结果为 `v3.7.0`；部署固定此稳定版本，不使用 `main` 或 dev 滚动版本。
- 3x-ui 支持 SQLite；裸机安装不需要 Docker，适合降低当前 1 GiB VPS 的额外开销。
- 3x-ui 面板支持 `webListen`、自定义面板端口和随机 Web 根路径；虽然支持 HTTPS 配置，本任务按用户决定使用原生 HTTP。
- 3x-ui 具备可选的 tunnel health monitor；本任务必须关闭主动探测。

## Requirements

- R1：所有安装、配置、启动、验证、备份和回滚操作只能针对 `vps` 执行；不得访问、探测或修改任何其他 SSH 目标、远程代理或外部 2260 服务。
- R2：安装 `3x-ui v3.7.0` 和其配套 Xray 时，使用独立目录、独立 systemd 服务和独立 SQLite 数据；不得覆盖 `/etc/sing-box/config.json`、`sing-box.service` 或其数据。
- R3：现有 VPS `sing-box.service`、`2262/tcp` 和 `2263/tcp` 必须保持运行；新服务不得抢占这些端口。
- R4：3x-ui 必须承担新用户入口、客户端凭据、订阅、流量统计、配额/到期控制和禁用能力；用户不得接触服务端私钥、数据库、API token 或其他管理配置。
- R5：新用户流量的实际出口为 VPS 本机 Xray `freedom/direct`；不依赖任何未确认的外部上游。
- R6：VPS 的 `2260/tcp` 定义为新建的 VLESS + Reality 入站；现有 `2262`/`2263` 和 SSH `22` 继续保留，不迁移、不替换。
- R7：3x-ui 面板允许公网使用明文 HTTP，但必须使用强随机管理员凭据、非默认高位端口、随机 Web 根路径和登录保护；必须明确记录凭据会以明文传输的风险，并优先启用 TOTP 2FA。
- R8：所有管理员密码、Xray UUID、Reality 私钥、订阅密钥和 API token 只能在 VPS 受保护路径中生成/保存；不写入任务文档、不回显到聊天、不进入普通日志或 shell 历史。
- R9：配置修改前必须创建带时间戳的 VPS 本地备份；失败时可以停止新服务并恢复新服务配置，不影响现有 sing-box。
- R10：验收只进行本机配置语法、systemd、监听端口、面板 HTTP 健康和现有服务状态检查；不发送真实代理请求、不测速、不查询出口 IP、不执行外部目标探测。

## Resolved decisions

### D1：控制面项目

采用 `3x-ui + Xray`，不再使用 RelayPanel。

### D2：部署边界

全程只操作 VPS；现有 VPS sing-box 和监听端口并行保留。

### D3：VPS-only 出口和 2260

在 VPS 上新建 Xray VLESS + Reality 入站 `2260/tcp`，所有新用户流量经 Xray `freedom/direct` 从 VPS 默认网络出口发送。现有 `2262`、`2263` 和 SSH `22` 不修改。

### D4：用户侧协议

使用 VLESS + Reality。SOCKS5/HTTP 不作为首版公网入口，如后续需要再增加独立端口。

### D5：面板暴露方式

用户明确允许面板直接使用公网 HTTP，并要求凭证校验。方案采用 3x-ui 原生 HTTP：

- `webListen=0.0.0.0`；
- 安装生成的非默认高位面板端口；
- 长随机 Web 根路径；
- 强随机管理员凭据、登录失败限制和 TOTP 2FA；
- 不生成或配置面板 TLS 证书；
- 面板端口不与 `22`、`2260`、`2262`、`2263` 冲突。

这会使管理员密码和会话在公网以明文传输，只适合作为用户明确接受风险的临时/受控方案；未来可以在不改变 Xray 数据面的情况下再加 HTTPS 或反向代理。

### D6：订阅子服务暴露方式

3x-ui 订阅子服务保留本地可用性，但固定绑定 `127.0.0.1:2096`，不对公网开放；初始客户端分享信息仅保存于 VPS root-only 文件或由管理员登录面板查看。

## Deferred items

面板明文 HTTP 的风险已由用户明确接受；后续如有域名或受控管理网络，优先升级到 HTTPS，不改变本任务的 Xray 数据面。
