# yesimbot-message-polisher

可选的完整回复表达插件，需与支持统一回复编排的 `koishi-plugin-yesimbot` 一同加载。复用当前完整 `PERSONA.md` 和 Roleplay 角色卡，不需要第二套人设。自定义 Persona 优先；只有角色卡时不混入默认 Athena。

## 启用后的分工

- **未启用本插件**：主 Agent 携带正常人设，一次提交完整的文字分条和可选表情顺序，不增加必选的表达模型调用。
- **启用并配置本插件**：主 Agent 负责判断、核对信息和执行工具，通过 `prepare_reply` 提交拟对外表达的 `facts`、交流动作 `intent` 和可选逐字内容 `verbatim`，不写角色草稿。独立表达模型携带完整人设，决定措辞、有意义的分条、是否使用表情及其位置；Core 校验后统一发送。

旧配置的 `mode: rewrite`、`mode: compose` 和缺省值现在都是**完整回复编排的兼容别名**，不再保留官方的固定条数改写或原稿兜底。无需改写配置文件；升级会改变已启用插件的表达行为，Core 与本插件应配套升级。第三方旧回调的兼容路径不等于本插件的行为。

```yaml
model: "providerId:modelId" # 独立的表达聊天模型；留空不启用
mode: rewrite # 旧值保留即可；rewrite/compose 均执行完整编排
temperature: 0.5
timeoutMs: 8000
```

`temperature` 范围 0–2，`timeoutMs` 范围 1000–60000 毫秒，限制单次表达生成。插件只用配置的独立模型，不回退到 Core 的 `auxiliaryModel` 或主模型。注册状态决定表达所有权：模型暂不可用、超时或输出无效时，本次不发送 facts、intent 或草稿，也不悄悄改由主 Agent 写台词。卸载通过正常 runtime 重建恢复主 Agent 表达。

## 分条、表情和查看

短而完整的回应可以只有一条；独立回应、转折或补充可以分条。不按空行、字数或标点机械拆分，也不强制变化。单次回复最多 12 个文字单元、1 张表情、13 个有序单元，正文总量最多 32 KiB；这些是安全上限，不是目标数量。完整代码、命令和必要精确引用必须留在同一文字单元。

表情可省略，也可单独、在文字前后或两段文字之间。必须先在本轮更早的已完成步骤实际查看同一候选；分类、搜索和主模型描述不算看过。表达模型可请求一次候选查看，再继续同一份准备，最多两次表达生成、整体 60 秒内有效。查看不意味着发送；一轮已确认或不确定地尝试发表情后，后续回复仍可正常生成纯文字。

已授权候选通过独立的有界视图交给表达模型：模型支持图片时接收真实帧，否则使用已有实际描述，或通过 Core 配置的 `visionModel` 描述同一帧。没有可用视图时只能纯文字；不会把分类模型当成发送前视觉证据。查看/视觉描述和额外工具步骤可能增加费用与延迟。

## 交付与历史边界

主 Agent 不接收 Persona/角色卡。表达请求只携带有界的当前回合用户参考、过滤后的非输出工具结果、拟对外信息及授权候选视图；不提供内部思考、assistant 工具参数、发送/准备结果、完整历史或持久化图片字节。

Core 保留频道、`raw/element`、`continue`、资源解析、节奏与发送所有权，整份回复先校验再按顺序交付。`verbatim` 必须完整保留并在实际输出表示中存活；数字、@、URI、标签的原文和次数也要符合校验。错误或取消立即停止，已经发送的前缀不重新生成或整批重发。

真正完整送达的单元通过真实平台 ID 和 Core 本地投递日志进入历史，即使 SDK 取消导致工具结果未保存，已提交的前缀仍可读。日志不是重发队列：磁盘故障或进程退出仍可能留下证明缺口；写入失败会停止后续发送，不承诺远端与本地原子提交。

## 独立的历史客观化

Core 的 `session.compact.assistantAsFacts: true` 配合 `auxiliaryModel`，可把所有保留的历史自身回复（含近期窗口）提取为客观记录并缓存，压缩及显式展开使用同一策略。失败只显示不可用元信息，不回退原话；原始 JSONL、当前用户和本轮工具续接不改写，既有摘要不自动重生成。默认关闭，与本插件启用状态独立。

协议和 mock 回归只能证明机制，不能证明真实模型一定自然分条、选对表情或语义无损。真实效果需要另行授权评估。详细所有权和限制见 [Prompt 架构](../../docs/prompt-architecture.md)。
